# Session 定义与管理规范

## Session 的定义

Session 是**任务执行的容器**，同时是用户可感知、可操作的工作单元。Session 不只是内部逻辑概念：

- 在支持多会话的 GUI 环境（Codex、opencode 等）中，子 Session 必须创建为**真实、可视化、用户可见的独立会话**
- 用户可以直接查看、切换、追问任何子 Session
- 在不具备多会话能力的环境中，才允许退化为内部子会话，但必须留痕

## Session 形态

| 形态 | 适用环境 | 要求 |
|------|---------|------|
| 可视化 Session | Codex、opencode 等支持多会话的 GUI 环境 | **必须**在界面中创建真实会话；使用稳定命名；状态对用户可见 |
| 内部子会话 | CLI 或不支持多会话的环境 | 在 `.m-work-flow/sessions/<session名称>/` 中建立对应目录，任务边界、报告、通信记录全部落盘 |

### 判定规则

1. 先判断当前环境是否支持创建真实的多会话。
2. 支持 → 必须可视化，不得在内部偷偷模拟。
3. 不支持 → 内部化 + 文件留痕，保证事后可追溯、可交接。
4. 无法判定时，向用户确认。

### 子 Agent 层级不受影响

无论 Session 采用哪种形态，子 Session 内部"子 Session 主 Agent → 任务执行 Agent / 质量验证 Agent"的调度关系不变；子 Agent 由所在 Session 内部调度，不强制每个子 Agent 都是独立会话。

## 专项 Session 与复用

### 专项原则

- 按业务域或问题域建立**专项 Session**，例如：`session-翻译功能`、`session-数据同步`
- 一个领域一个专项 Session，避免碎片化新建
- 同一领域的后续 BUG 修复、功能完善，优先复用已有专项 Session

### 生命周期

```
创建 → 执行中 → 已验收 → 待复用 ──→ 重新激活 → 执行中 → ...
                      │
                      └──→ 关闭（用户明确要求或领域废弃）
```

- **已验收 ≠ 销毁**：完成验收的 Session 默认进入"待复用"，保留全部上下文
- **重新激活**：主 Session 向原 Session 下发新的标准任务边界即可，沿用既有上下文
- **关闭条件**：仅当用户明确要求关闭，或该业务域永久废弃时才关闭

### 复用的收益

- 上下文延续：不重复分析项目结构、不重读代码
- 测试结论延续：上一轮质量验证报告可直接引用（衔接测试唯一责任制）
- 历史可追溯：用户可在原会话直接查看历史决策和修改记录
- 降低复杂度：减少新建会话带来的拆解、介绍和上下文重建成本

### 复用规则

1. 新建 Session 前，必须先查 `.m-work-flow/sessions/registry.md`，确认是否已有同领域待复用 Session。
2. 有 → 优先重新激活复用；无 → 新建。
3. 复用时必须在原 Session 中下发标准任务边界格式的新任务，不得沿用过期边界。
4. 跨领域的紧急小修复，经用户同意后可新建一次性 Session，完成后按领域归属决定是否纳入注册表。

## Session 注册表

主 Session 必须维护 `.m-work-flow/sessions/registry.md`，并在创建、激活、验收、关闭时更新：

```markdown
# Session 注册表

| Session 名称 | 领域 | 状态 | 创建时间 | 最近活动 | 复用次数 | 备注 |
|-------------|------|------|----------|----------|----------|------|
| session-翻译功能 | 翻译 | 待复用 | <日期> | <日期> | 2 | 悬停+自动翻译 |
```

状态取值：`执行中`、`已验收`、`待复用`、`已关闭`

## 命名规范

- 格式：`session-<领域名>`，例如 `session-翻译功能`
- 名称必须稳定、语义清晰，复用时不得变更
- 同一领域同时只允许一个活跃专项 Session

## GUI 展示要求

- 可视化 Session 的会话名称必须使用注册表中的稳定名称
- 会话内角色展示遵循稳定职能名称规范，例如：`Session:session-翻译功能｜任务执行 Agent｜工作中`
- 主 Session 向用户展示各子 Session 进度时，使用注册表中的状态值
