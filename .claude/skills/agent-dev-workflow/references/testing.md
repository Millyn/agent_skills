# 测试规范

## 测试策略选择

### 小型项目

可以进行较完整的全项目测试。

重点确认：
- 程序是否能够正常启动
- 核心流程是否能够正常执行
- 是否发生程序崩溃
- 是否存在资源加载失败
- 是否存在资源路径错误
- 是否存在明显运行时错误
- 是否存在新增功能导致的流程异常

### 大型项目

不需要默认对整个项目进行全面测试。

应优先测试：
- 本次修改涉及的模块
- 本次修改影响的调用链
- 与本次修改直接相关的功能
- 修改涉及的资源、数据、关键流程

**目的：减少不必要的 Token、运行时间和计算资源消耗。**

对于未修改、且与本次修改没有直接关联的大量功能，不需要为了"全面测试"而重复验证。最终可以要求用户自行执行完整项目测试。

## 测试范围

默认情况下，测试 Agent 主要关注程序功能和运行稳定性。

### 程序运行

确认程序能够正常启动和运行。

### 流程完整性

确认修改后的流程不会发生明显中断或崩溃。

### 资源加载

确认：
- 图片能够正常加载
- 音频能够正常加载
- 配置文件能够正常加载
- 数据文件能够正常读取
- 依赖资源路径正确

### 错误检查

重点关注：
- Runtime Error
- 程序崩溃
- 空引用
- 文件不存在
- 资源不存在
- 配置错误
- 数据格式错误
- 接口调用错误
- 明显的流程异常

## 性能测试原则

除非用户明确要求，否则默认不进行专门的性能测试。

### 不默认进行的测试

- Benchmark
- 压力测试
- 大规模并发测试
- 长时间运行测试
- CPU/GPU 性能分析
- 内存性能分析
- 极限负载测试

### 需要性能测试的情况

- 用户明确要求性能优化
- 当前修改明显涉及性能
- 项目本身存在明确性能问题

**首要保证程序功能正确，而不是为了性能测试消耗额外 Token 和计算资源。**
