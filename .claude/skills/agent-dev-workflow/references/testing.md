# 测试规范

## 测试范围决策

### 分配前的影响分析

流程统筹 Agent 在分配任务时，必须明确：

- **修改范围**：实际允许变更的模块、文件或功能。
- **影响范围**：修改直接影响的调用链、依赖模块、资源、数据或用户流程；无法确认的部分应标明待验证风险。
- **测试目标**：需要验证的行为、验收标准和主要风险。
- **测试边界**：本次默认不覆盖的模块、流程或非直接相关功能。

质量验证 Agent 必须依据上述信息制定测试，并在发现实际影响超出分配范围时先记录风险，必要时向流程统筹 Agent 汇报后扩大测试范围。

### 默认测试策略

用户未明确要求全量回归时，质量验证 Agent 默认执行定向测试，范围按以下优先级确定：

1. 修改范围内的单元、模块或功能测试。
2. 修改直接影响的调用链、依赖模块、资源、数据和关键用户流程。
3. 为确认程序可启动、主流程未被破坏而进行的必要的最小冒烟验证。

不得仅因为项目规模、测试命令默认行为或“全面测试”的惯例，一味执行全项目测试。与本次修改没有直接关联的功能不属于默认测试范围。任何超出分配测试边界的测试，都必须在报告中记录实际扩大范围和扩大理由。

### 全量回归触发条件

以下情况必须全量回归，或在无法执行时由流程统筹 Agent 明确记录风险并说明替代验证方案：

- 用户明确要求全量回归或完整项目测试。
- 修改涉及全局配置、构建流程、依赖版本、公共基础设施、通用组件或跨模块契约，影响范围难以限定。
- 修改涉及数据格式、数据库结构、迁移、公共接口或核心状态管理，可能影响多个未直接修改的功能。
- 修改范围或影响范围无法可靠识别，且定向测试不足以证明系统整体可用。

以下情况建议全量回归，由流程统筹 Agent 根据风险、成本和项目约束决定，并记录决定理由：

- 修改跨越多个业务域或多个端（例如前端、后端、任务执行链路）。
- 修改核心启动流程、认证授权、路由、资源加载或错误处理等公共链路。
- 定向测试发现回归问题，或变更触及大量既有测试。
- 发布前、版本验收或用户明确关注整体稳定性。

除用户明确要求外，选择全量回归不是默认义务；选择定向测试也必须说明依据的修改范围和影响范围。

## 测试策略选择

### 小型项目

可以进行较完整的全项目测试。

重点确认：
- 程序是否能够正常启动
- 核心流程是否能够正常执行
- 是否发生程序崩溃
- 是否存在资源加载失败
- 是否存在资源路径错误
- 是否存在明显运行时错误
- 是否存在新增功能导致的流程异常

### 大型项目

不需要默认对整个项目进行全面测试。遵循本规范“测试范围决策”确定定向测试或全量回归。

应优先测试：
- 本次修改涉及的模块
- 本次修改影响的调用链
- 与本次修改直接相关的功能
- 修改涉及的资源、数据、关键流程

**目的：减少不必要的 Token、运行时间和计算资源消耗。**

对于未修改、且与本次修改没有直接关联的大量功能，不需要为了"全面测试"而重复验证。最终可以要求用户自行执行完整项目测试。

### 测试范围记录

质量验证 Agent 的完成报告必须记录：

- **实际测试范围**：实际执行的修改范围、直接影响链路、相关资源或数据，以及必要的最小冒烟验证。
- **未测试范围及原因**：按测试边界列出未覆盖内容，并说明是因为与修改无直接关联、环境或依赖不可用、时间成本、风险评估，还是其他具体原因；没有未测试范围时填写“无”。
- **范围扩大及理由**：如实际测试超出分配的测试边界，必须列出新增范围和扩大理由。

报告不能只写“测试通过”或只列测试命令而省略覆盖范围。

## 测试范围

默认情况下，测试 Agent 主要关注程序功能和运行稳定性。

### 程序运行

确认程序能够正常启动和运行。

### 流程完整性

确认修改后的流程不会发生明显中断或崩溃。

### 资源加载

确认：
- 图片能够正常加载
- 音频能够正常加载
- 配置文件能够正常加载
- 数据文件能够正常读取
- 依赖资源路径正确

### 错误检查

重点关注：
- Runtime Error
- 程序崩溃
- 空引用
- 文件不存在
- 资源不存在
- 配置错误
- 数据格式错误
- 接口调用错误
- 明显的流程异常

## 性能测试原则

除非用户明确要求，否则默认不进行专门的性能测试。

### 不默认进行的测试

- Benchmark
- 压力测试
- 大规模并发测试
- 长时间运行测试
- CPU/GPU 性能分析
- 内存性能分析
- 极限负载测试

### 需要性能测试的情况

- 用户明确要求性能优化
- 当前修改明显涉及性能
- 项目本身存在明确性能问题

**首要保证程序功能正确，而不是为了性能测试消耗额外 Token 和计算资源。**
